# R3877.52.1 — macOS temporary-directory symlink test fixture correction

**Research / educational use only. `NOT_BOOTABLE` unchanged.**

## Root cause and fix

User's Mac reported 40 tests run with **15 failures and 14 errors**; the common cause was `AuditHold('SYMLINK_REJECTED')`. This is reproducible on Linux using an artificial symlink ancestor for `TMPDIR`. On macOS, `tempfile.TemporaryDirectory()` often returns a `/var/...` path, whose ancestor `/var` is a system alias to `/private/var`. The production `limited_file()` intentionally rejects a symlink anywhere in a file's pathname, so the test fixture could not even reach the intended synthetic assertions.

**Only `test_r3877_52.py` is changed:** the fixture path now uses `Path(self.temp.name).resolve(strict=True)` before creating its synthetic source files and receipt. The production auditor, `limited_file()`, source hash pins, `NOT_BOOTABLE` and the host-only fetcher remain **byte-identical to R3877.52**. The original 40 tests are retained, plus tests for the canonical fixture root and rejection of deliberately symlinked input parents. No symlink-security safeguard has been relaxed.

The same failure was reproduced using `TMPDIR` referencing an artificial symlink parent on Linux, before the fix; the updated suite passes under that simulated macOS condition.
