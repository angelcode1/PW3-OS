# R3877.18.1 — SSH reset / timeout diagnosis

**Research and educational use only. `NOT_BOOTABLE`.**

## Historical, user-reported observations

The user's local R3877.18 runtime audit did not reach ELF analysis. Two subsequent SSH attempts to the existing `root@192.168.8.102:2222` endpoint returned `SSH_CONNECTION_TIMED_OUT` and then `SSH_CONNECTION_RESET`, each with exit 255. The previous R3877.17.2 local symbol-version audit had succeeded against this endpoint, so these SSH errors **do not demonstrate** missing ELF exports, KOReader incompatibility, firmware damage or an Alpine userspace failure. The 12-second connection timeout in the older package may have been too short for the device to resume networking, but a longer timeout cannot repair a genuine reset.

## Correction

R3877.18.1 keeps the symbol/relocation parser and the fixed-scope application/system-library tar collection unchanged. It adds a dedicated **one-SSH, no-tar** health probe that executes only the pre-existing `uname` and shell built-ins, validates `3.0.35-lab126` and `armv7l`, and reports `PASS_SSH_HANDSHAKE_ONLY` when connected. This is not an ABI or runtime pass.

The regular collection now uses an explicit 20-second SSH connection timeout (configurable between 5 and 60 seconds), still only one connection attempt. On SSH failure it reports the exit code, sanitized error classification, stderr byte count/hash and **partial stdout byte count** so that a failure before archive output can be distinguished from an interrupted archive stream. Partial bytes are never copied into output, logged to disk or treated as valid evidence; no retry occurs. A zero partial-output length does not prove whether authentication or tar failed. The single SSH session cannot by itself distinguish target sleep, network interruption, sshd reset or shell/tar resource failure.

## Run on macOS

```sh
mkdir -p ~/Downloads/pw3-r3877-18-1
unzip -oq ~/Downloads/pw3-r3877-18-1-ssh-reset-diagnostic.zip -d ~/Downloads/pw3-r3877-18-1
cd ~/Downloads/pw3-r3877-18-1
shasum -a 256 -c SHA256SUMS_R3877_18_1.txt
python3 -B -m unittest -q test_r3877_15.py test_r3877_16.py test_r3877_17.py test_r3877_17_1.py test_r3877_17_2.py test_r3877_18.py test_r3877_18_1.py

# After physically waking PW3, run the lightweight probe first:
set -o pipefail
python3 -B pw3_r3877_18_1_relocation_candidates.py \
  --target root@192.168.8.102 --port 2222 \
  --authorize-live-readonly-ssh --probe-ssh-only \
  | tee r3877_18_1_ssh_probe.json
echo "SSH_PROBE_EXIT_CODE=$?"

# Only if the lightweight probe passes, attempt fixed-scope archive once:
python3 -B pw3_r3877_18_1_relocation_candidates.py \
  --target root@192.168.8.102 --port 2222 \
  --connect-timeout 20 --authorize-live-readonly-ssh \
  | tee r3877_18_1_relocation_result.json
echo "R3877_18_1_EXIT_CODE=$?"
```

If the probe fails, **do not rerun the larger archive immediately**. Investigate local Wi-Fi and SSH reachability without changing firmware or sshd. `PASS_SSH_HANDSHAKE_ONLY` only verifies shell and basic communication. A reset on the archive with nonzero partial stdout suggests the stream started, but does not prove a specific root cause. Avoid changing sshd, installing binaries or modifying the PW3 to address a transport error.

No original R13 stage is accessed. No new target binaries are installed or executed, and only the existing `/bin/sh`, `uname` and `tar` commands are used. No personal books/settings are collected. Only the user's Mac-side `tee` writes a local JSON report.
