# R3877.18.2 — Classify strict ELF symbol candidate misses

**Research/educational use only. `NOT_BOOTABLE`. No firmware changes, boot attempts, target installs, host binfmt changes, or executing new Kindle binaries.**

## Observed historical results (user-reported, not recreated in CI)

R3877.18.1 completed one lightweight SSH probe and then one fixed-scope archive audit on the PW3 running `3.0.35-lab126` (ARMv7). The archive delivered all 38 KOReader and seven stock system ELF files. The local analyzer saw 60,482 allocated relocation entries, including 3,389 distinct strong relocation-bound dynamic imports. In its strict per-object DT_NEEDED graph, 3,222 strong imports had candidates and **167 lacked candidates**. The result is a HOLD, **not** a statement that the 167 imports will fail to link at runtime. There were also 163 weak imports without candidates; weak imports may legitimately be unavailable.

Examples include Lua API symbols (`lua_pcall`, `luaL_register`) imported by `libkoreader-cre.so` and `clock_gettime@GLIBC_2.4` associated with `librt.so.1`. The former may come from globally visible symbols in the main `luajit` executable; the latter requires a specific inspection of the named provider's exported dynamic symbols, symbol type and GNU version. Neither hypothesis has been proven by the previous JSON alone.

## What this package does

It retains the complete R3877.18.1 read-only archive transport and parser, and then **recomputes** all strong candidate misses from a separate indexed export lookup. A consistency check enforces that both analyses agree on file count, strong/weak totals, and the original number of missing strong candidates; disagreement fails closed.

Each strict-scope miss is classified with bounded samples, including:
- Potential main `luajit` executable export outside the strict per-DSO dependency graph
- Export in another collected library outside the strict graph
- Named GNU-version provider outside scope, with the wrong version/type, or not exporting the name
- Symbol name present but incompatible type/version, or no such export found in the collected set

The classification is **not** glibc dynamic-linker emulation: actual main executable global visibility, load order, `dlopen` module closure, versioned binding, relocation application, syscall/TLS compatibility and recovery remain unverified.

## Mac usage

```sh
mkdir -p ~/Downloads/pw3-r3877-18-2
unzip -oq ~/Downloads/pw3-r3877-18-2-scope-classification.zip -d ~/Downloads/pw3-r3877-18-2
cd ~/Downloads/pw3-r3877-18-2
shasum -a 256 -c SHA256SUMS_R3877_18_2.txt
python3 -B -m unittest -q test_r3877_15.py test_r3877_16.py test_r3877_17.py test_r3877_17_1.py test_r3877_17_2.py test_r3877_18.py test_r3877_18_1.py test_r3877_18_2.py
set -o pipefail
python3 -B pw3_r3877_18_2_scope_diagnostic.py --target root@192.168.8.102 --port 2222 --connect-timeout 20 --authorize-live-readonly-ssh | tee r3877_18_2_result.json
echo "R3877_18_2_EXIT_CODE=$?"
```

If the Kindle has gone to sleep, the optional `--probe-ssh-only` mode executes only a read-only `uname` sequence, with no archive. Only run the larger archive once SSH is reachable.

Success means **`PASS_SCOPE_CLASSIFICATION_METADATA_ONLY`**. This only establishes a complete classification of the previously strict-scope missing symbols. If some symbols have no candidate, they are still **unresolved**, and `NOT_BOOTABLE` is unchanged.
