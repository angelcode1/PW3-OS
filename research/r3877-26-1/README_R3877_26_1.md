R3877.26 `--inputs-only` returned `PASS_PINNED_APORTS_INPUT_BYTES_ONLY` with 13 verified inputs (upstream musl 1.2.6 release tarball, 6 Alpine patches, 5 helpers, and pinned APKBUILD). ## Root cause and correction

R3877.26 treated the old `@@ -line,count` hunk line as a mandatory absolute location. Real Alpine patches may use source line hints from different upstream revisions. For example, the first `handle-aux-at_base.patch` hunk requests around line 66 but its **entire old hunk** matches uniquely about six lines later in the public musl v1.2.6 Git file. Similar small offsets occur in the pinned LoongArch64 and regex patches. This does not mean source context is missing.

R3877.26.1 requires the *complete, unchanged old hunk*, including context and removed lines, at **exactly one** location in the file. Every candidate is checked without context trimming, fuzz, partial matching or substitutions. Mismatching or repeated context fails closed. Every offset must be within 128 lines of the hunk's predicted location; non-create empty-context hunks are refused. New-file hunks must start with an empty target. The report now includes relocated hunk counts and bounded samples. Patch order, Git-blob/SHA512 validation, archive safety, no target execution and all hold statuses are preserved.

**Important:** The tests include synthetic fixtures and were compared against pinned upstream Git source *text*. They do not establish that the actual release tarball's full patch sequence passes until the user runs the corrected audit on the previously verified downloads.
