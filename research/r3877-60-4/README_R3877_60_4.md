# R3877.60.4 — Host-ENOSYS selftests and QEMU statx-emulation classification

Research/education, **Mac/Colima only**. The Kindle remains **NOT_BOOTABLE**. Never use this on the Kindle. No Kindle SSH, firmware writes, boot, recovery, privileged Docker, host bind mounts, guest network or host binfmt registration. Default invocation refuses Docker/ARM execution with HOLD.

## Why previous R3877.60.3 held

User's live Colima result saw 1 guest `getrandom` returning ENOSYS and 1 guest `statx` returning success. Both independent controls passed, four guest containers exited 0, seccomp filter installed, auxiliary isolation and anonymous-volume cleanup passed. Previous harness expected guest `statx` to return ENOSYS; that is incorrect for pinned QEMU 10.0.4 because `linux-user/syscall.c` specifically calls `fstatat` after host `sys_statx` returns ENOSYS. Exact upstream Git blob `3a25abfaca2ef9f0a049cc38e74133c3187aaca7` (`qemu/qemu`, tag `v10.0.4`, path `linux-user/syscall.c`). This is a **QEMU-specific emulation**, not proof of guest or physical Kindle kernel `statx` support. Unclassified trace lines remain unattributed.

## What changed

A new freestanding AArch64 seccomp launcher retains the same nine-instruction filter, but directly calls raw host `getrandom` and `statx` **after installing the filter and before execing pinned QEMU**. Each must return `-ENOSYS` (Linux AArch64 `-38`), or it exits HOLD (not success). Only exact allowlisted markers are accepted. The new launcher is SHA-256 `b9a433e2397e27c4cbdd2aade7b57cc39af4e6f36b37a4f204833b282a987b02` and mode 0755. The previous launcher and ARMv7 probe are unmodified. Guest `getrandom` must be observed exactly once returning ENOSYS; guest `statx` must be observed exactly once without ENOSYS and the corresponding BusyBox stat untraced control must pass. A PASS attests the host deny plus observed guest behavior under pinned QEMU; it **does not** prove QEMU's exact internal branch from the trace alone, runtime musl `getentropy` fallback, ARM vendor Linux 3.0.35 syscall compatibility or recovery.
