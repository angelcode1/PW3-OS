## Evidence and reason for change

The user's real Mac R3877.60.1 result was `HOLD`, `HELPER_CONTAINER_ISOLATION_UNVERIFIED`: 16/17 auxiliary checks passed, **only `mounts_absent` was false**; filter installation and ARM execution did not occur. Note: Docker anonymous volumes may outlive `docker rm` without `-v`; the old report does **not** attest their deletion. Do not run `docker volume prune` or delete unspecified volumes.

Docker can create anonymous volumes from a pinned image's `Config.Volumes` even when `docker create` specifies no mounts. R60.2 checks that hypothesis **against the exact inspected image**, not by guessing or bypassing the guard.

## New, narrowly scoped mount policy

The helper and preparation containers are **stopped-only**, and require all earlier isolation checks plus:

* No bind mounts, explicit `HostConfig.Mounts`, `VolumesFrom`, `Tmpfs`, or user volumes.
* Any `Mounts` entries must match image-declared `Config.Volumes` destinations **one to one**, with type `volume`, Docker `local` driver, a 64-character hexadecimal anonymous volume name, and a Docker-managed source corresponding to that name. Named volumes, binds, network drivers, unknown types/sources, extra destinations, or mounts hiding the pinned executable remain **HOLD**.
* Reports disclose only classifications, booleans and counts, never raw Docker source paths, anonymous volume IDs or container IDs.
* Containers are removed using `docker rm -f -v`. For each *verified newly observed anonymous volume*, `docker volume inspect` must confirm it no longer exists. Missing or unclassified mount metadata gives HOLD, and does **not** establish volume cleanup. No broad or destructive cleanup is attempted.

This allows only verified Docker-managed volumes **inside Colima**, not Mac host-file sharing. It is an explicit relaxation of `mounts_absent`, **not** of the `no host bind mounts` rule. If the actual helper mount is anything else, R60.2 stops and prints a stable `mount_classification` explaining the refusal.

The rest of R60.1's security and runtime protocol (Docker default seccomp, pinned image/ARM/QEMU/filter hashes, no guests started before inspection, EROFS gate with separate disposable writable-layer authorization, syscall trace predicates, cleanup) remains unchanged. The legacy Kindle kernel is **not** emulated by Colima QEMU.
