# R3877.78.1 — Alpine armv7 musl SONAME correction

**Research/educational use only. HOLD / NOT_BOOTABLE remains mandatory.**

## What failed

R3877.78 user-reported:
- `archive_sha256_verified: true`
- `hold_category: PINNED_ARCHIVE_OR_ELF_VALIDATION_REFUSED`
- `device_execution_attempted: false` and exit code 2.

The SHA-256 matches the pinned Alpine 3.24.2 armv7 minirootfs. The original
validator incorrectly expected the Alpine **armhf** libc SONAME,
`libc.musl-armhf.so.1`, for an **armv7** BusyBox. This is a validation defect,
not proof of Kindle incompatibility.

Alpine armv7 uses these **different names**:

- Dynamic interpreter/loader: `/lib/ld-musl-armhf.so.1`
- BusyBox `DT_NEEDED` libc: `libc.musl-armv7.so.1`

The correction retains the loader name and updates only the libc dependency,
staging copy name and Kindle-side references. Added four synthetic regression
tests (20 total), and a separate archive-only mode with safe refusal codes.

Sources:
- https://pkgs.alpinelinux.org/contents?arch=armv7&branch=v3.19&name=musl&repo=main
- https://pkgs.alpinelinux.org/package/v3.23/main/armv7/busybox
- https://github.com/pragyaangaur/Inkwell/blob/main/tools/fetch.sh
