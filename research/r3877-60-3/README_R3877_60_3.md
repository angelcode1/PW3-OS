# PW3-OS R3877.60.3 — repair launcher execute-mode packaging and preserve startup diagnostics

**For research and educational purposes only. `NOT_BOOTABLE` remains immutable for the physical Kindle.** This test is Mac/Colima-only, uses QEMU and the host Linux kernel, and performs **no Kindle access, native Kindle binary execution, firmware writes, boot, recovery, host binfmt registration, guest network, host bind mounts, privileged containers, image pulls or host seccomp-profile changes**. Default invocation returns HOLD without Docker.

## Evidence

The user's Mac R3877.60.2 result verified helper and preparation isolation, Docker builtin seccomp, the exact pinned image, successful container and anonymous-volume cleanup. It then stopped at `GUEST_EXIT_OOM_STATE_UNVERIFIED:arm_control`, before `host_seccomp_injection_performed` or ARM guest execution. **The precise Docker startup state was not reported**, so the error cannot be causally attributed from that JSON alone.

Inspection of the exact prior R3877.60.2 release archive shows `pw3_r3877_60_aarch64_seccomp_launcher.elf` was packaged with Unix mode `0644` (no executable permission). Its bytes were correct, but it was being copied to the guest and used as Docker's entrypoint. Docker could therefore reject startup with permission denied. The ARM ELF probe likewise arrived as `0644`. R3877.60.3 preserves **all ELF bytes and SHA-256 pins** and repackages both executable files with `0755` permissions.

## New fail-closed checks

- The local AArch64 launcher, ARMv7 probe and helper-sourced QEMU must be executable by the unprivileged guest (`--user 65534:65534`), with no group/world write access.
- After Docker copies the three files into a still-stopped container, each **readback's executable mode and SHA-256** must match before the container may start. Missing mode causes HOLD.
- The first `docker start --attach` result now records bounded, sanitized `guest_start_diagnostics.arm_control` fields: start exit code, output bytes/hash, a narrowly allowlisted error class (`DOCKER_START_PERMISSION_DENIED`, `DOCKER_START_EXEC_FORMAT_ERROR`, `DOCKER_START_MISSING_FILE_OR_INTERPRETER`, `DOCKER_START_OPERATION_NOT_PERMITTED`, or unclassified), status (`created`, `exited`, etc.), `Running`, `OOMKilled`, exit code, and an error-present boolean. Raw guest output, image paths, IDs and Docker stderr are not published.
- Any guest state that is not verified `exited`, `Running=false`, `OOMKilled=false` still produces HOLD, as in R60.2.
- The R60.2 image-declared anonymous volume policy, `docker rm -f -v`, volume cleanup attestation, builtin Docker seccomp checks, restricted guest capabilities and no-new-privileges **remain enforced**. The AArch64 seccomp filter launcher itself is byte-identical.

This update addresses a known release permission defect. **It does not claim that the prior HOLD was caused by that defect, nor that `getrandom`/`statx` ENOSYS simulation has passed.**
