# PW3-OS R3877.59.1 — Diagnose R59 ARM pthread/TLS QEMU HOLD

**Host-only, for research and education. `NOT_BOOTABLE` remains immutable for the Kindle.** Do not install or execute this test on a Kindle, change firmware/eMMC, or infer vendor Linux 3.0.35 syscall behavior from Colima QEMU.

## Observed input

The user's authorized R59 Mac run reached the ARM guest, then returned `HOLD` / `GUEST_PROBE_FAILED:r59_probe_control` (exit 2 for the wrapper). The parent image was unchanged and all temporary containers were removed. The R59 wrapper failed to report the original ARM process exit code or its output diagnostics, even though the underlying R49 runner held those fields. The root cause (loader failure, TLS, pthread, unexpected output, etc.) **is unknown**.

## Corrective scope

This release **does not change or rebuild the target ARMv7 ELF, R59 runner, or pinned R49 isolation and cleanup runner.** The R59 file SHA-256, probe ELF SHA-256, and R49 source SHA-256 are checked. A diagnostic wrapper captures the underlying R49 failed control record and the exact own-message markers from the ARM probe. Any other guest output is reduced to length, SHA-256 and count of unrecognized lines. It does **not** publish raw stdout/stderr, guest paths, arbitrary strings or error messages. The new wrapper never promotes a failure to PASS and does not attempt automatic retries or kernel changes.

If the process exit code is `11`, `12`, `13`, `14`, or `15`, and the corresponding marker appears, that narrows the failure to the program's own marked branch. Exit 127 or a missing marker might indicate a startup, loader, permission, crash, or diagnostic-attribution issue, but it does not prove any specific cause. The wrapper's exit 2 is a HOLD distinct from the guest process exit status.
