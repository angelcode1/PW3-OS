# PW3 R3877.49.3 — Restore proven BusyBox applet argv before QEMU syscall traces

**Research and educational purposes only. `NOT_BOOTABLE` remains unchanged.** Do not modify Kindle firmware, bootloader, partitions, rootfs or physical hardware. No Kindle SSH, privileged Docker, host mounts, guest networking, binfmt registration or container image creation is performed.

## Why R3877.49.2 held

The user-reported R3877.49.2 Mac output stopped on `busybox_true_control` (exit 0, unexpected 2,968 bytes). Its output SHA-256 `f5ff598da419a795d590934c471c8e99ecb595dfe701bf5e2d891df19cf5031d` **exactly matches** the earlier R3877.47 successful **forced-argv0 BusyBox help** probe. A zero exit code without exact stdout matching was correctly a HOLD. The R49.2 code had introduced `-0 /bin/busybox` for all applet probes, whereas the R47 successfully verified `qemu-arm-static /bin/busybox true`, `uname -m` and `echo` **without** `-0`.

R49.3 restores that demonstrated applet argv without otherwise changing the container isolation and immutable pinned binaries. This is a focused hypothesis about the harness; the cause of the QEMU/BusyBox argv0 behaviour is not conclusively proven by the digest match. In particular, **no source-level or target-kernel inference** is made. The exact historical R49.2 HOLD evidence is preserved in `R3877_49_2_USER_REPORTED_SELECTED_HOLD.json`.

## Test design

1. Default invocation must return exit 2 / HOLD and invoke **zero** Docker operations.
2. The authorised test rechecks the same cached ARMv7 parent and AArch64 helper identities, pinned BusyBox/QEMU ELF headers, and SHA-256 bytes. It begins with a read-only stopped guest, confirms and classifies any rejected QEMU copy, and uses a disposable writable layer **only with explicit additional opt-in** and a freshly matched read-only failure.
3. `true`, `uname -m`, and a unique `echo` marker run **without `-0`**, matching R47's successful invocation pattern. Exact stdout and exit values must match (no trailing help, stderr or unexpected text).
4. The three corresponding traced probes add QEMU `-strace` before `/bin/busybox` but never force `argv0` and must yield syscall records. Unknown names and ENOSYS counts are retained. Unclassified trace-stream bytes remain reported as unresolved, never converted into proof of clean applet stdout. `trace_output_separation_verified` remains `false` even after a narrow PASS.
5. All guests are nonprivileged, networkless, `--cap-drop ALL`, `no-new-privileges`, resource-limited, no mounts or devices. Docker inspect enforces expected arguments, images and policies before starting. The only allowed disposable filesystem differences are the injected pinned QEMU executable and ancestor directories. All temporary containers must be deleted and verified absent; original parent ID unchanged.
