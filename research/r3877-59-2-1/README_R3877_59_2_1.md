# PW3-OS R3877.59.2.1 — macOS GNU readelf test dependency repair

**Host-side test harness only.** Fixes user-reported `FileNotFoundError: readelf` on macOS Python 3.9 when running `test_09_old_has_no_needed` in the R3877.59.2 suite.

The original test silently skipped its assertion if `readelf` existed but returned nonzero. This release **replaces the external readelf call with a strict, pure Python ELF32 little-endian program-header and `PT_DYNAMIC` parser**, and requires the original R59 probe to contain no `DT_NEEDED`. It also asserts the corrected probe contains exactly one `DT_NEEDED`, rejects corrupt headers, and checks that no external process is invoked during this particular regression test.

**Preserved, byte-for-byte unchanged:** both ARM ELFs, the R49.3/R59/R59.1/R59.2 runtime scripts, C probe source, ELF base64, QEMU runtime logic, isolation and cleanup policies, and `NOT_BOOTABLE`. Only the host test file is changed relative to R59.2 (along with README/workflow/release checksums).

The test suite verifies the *offline harness*; it is not ARM execution. `getrandom()` ENOSYS fallback, physical Kindle Linux 3.0.35 compatibility, original patched musl reproducibility and recovery remain unverified. No Kindle SSH, firmware writes or boot operations. Research and educational purposes only.

## Why the prior run held: exact error-fingerprint match

The user's R3877.59.1 guest returned exit **127** with **740** output bytes, **9** unrecognized lines, and output SHA-256 `c5a0eb0c4ac06bc5154e324411a4df0dbce3fd56402ec3b023367633d2971332`. The original probe ELF had **nine undefined dynamic imports and no DT_NEEDED entry**. Reconstructing musl's own **known relocation-error format** for those nine symbol names in the ELF's relocation order (and for the known disposable guest path) gives **exactly 740 bytes and the same SHA-256**. This is exact evidence of unresolved dynamic imports; not pthread/TLS execution failure. No raw guest output was published.

The public upstream musl v1.2.6 dynamic linker explicitly recognizes `libc.so` as itself, and processes `DT_NEEDED` dependencies when adding symbols to the global namespace (`ldso/dynlink.c`, Git blob `715948f4f8b3e9b6aff8303b0d0bef6d5fe63cf8`). The corrected probe is linked with an explicit **single `DT_NEEDED: libc.so`** and retains `PT_INTERP=/lib/ld-musl-armhf.so.1`, `PT_TLS`, ELF32 ARM EABI5 hard-float. It is a **new** 4,464-byte hash-pinned file with SHA-256 `b0b89626cd48482e99ea8515b4c808c378e1ff65b4ea4de05b16a4c373df18f4`; original 4,288-byte probe remains unchanged (`5ce343387f982330965aa1d101daf15d1d53fd38de329d8e7c14a30d6cd37085`). The code and expected markers are the same as R59.

To cause a `DT_NEEDED` with no external target sysroot, the host link used an **empty, link-time-only shared object with SONAME `libc.so`** and `--no-as-needed`, and permitted unresolved imports for the target musl loader to resolve. **The placeholder library is NOT shipped to or copied into the QEMU guest.** The guest only gets the pinned QEMU helper and the corrected probe; its existing pinned Alpine musl loader resolves `libc.so`. The authoring compiler is Clang 17/lld 17, but its full provenance/reproducibility has NOT been independently attested.

## Safety and scope

- Default is HOLD / exit 2 and performs no Docker operation.
- Explicit QEMU opt-in is required; explicit *additional* `--allow-disposable-writable-layer` is required if `docker cp` into a read-only guest is rejected with the recognized read-only-rootfs error.
- Exact R49, R59, and R59.1 runner source hashes are checked. Only the hash-pinned ARM probe bytes are temporarily substituted. The original guest path, strict stdout control, pinned parent/helper identities, no host mounts or guest network, nonprivileged UID, capabilities, resource limits, cleanup and original image checks are inherited.
- The corrected ELF is inspected offline: `PT_INTERP`, `PT_TLS`, hard-float ABI, one `DT_NEEDED: libc.so`, no RPATH/RUNPATH, bounded loadable string table and unchanged original probe.
- If runtime fails, the R59.1 diagnostic is preserved: exit code, output digest, and *only recognized probe markers*. No raw program/trace output appears in the report.
- A possible PASS validates pthread/TLS plus host-kernel `getrandom`/`getentropy` on QEMU. It does **not** establish `ENOSYS` fallback, installed patched-musl provenance, Kindle kernel dispatch or recovery. Physical Kindle remains `NOT_BOOTABLE`.
