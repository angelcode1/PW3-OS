# R3877.49.2 — Independent applet controls beside incomplete QEMU syscall traces

Research / educational purposes only. **`NOT_BOOTABLE`** remains immutable. **No Kindle SSH, boot, kernel, firmware, disk writes, privileged Docker, networked guest, or host-device/bind mounts.**

## Why this test exists

The user's R3877.49.1 explicitly authorized Colima run reported `HOLD` at `busybox_true_trace`, even though it ran the QEMU guest and parsed **655 syscall records**, **nine distinct names** (`brk`, `dup2`, `exit_group`, `getuid32`, `ioctl`, `mmap2`, `mprotect`, `set_tid_address`, `write`), and **zero parsed `ENOSYS` and unknown-syscall records**. Its output parser retained **51 unclassified stdout lines** (48 nonblank), totaling 669 bytes after the line-based classification. Those are **not known to be application output** and **not proven to be QEMU-only trace formatting**. The failure is preserved in `R3877_49_1_USER_REPORTED_SELECTED_HOLD.json`; the 655 records are observational evidence, **not a syscall ABI success certificate**.

Official QEMU user-mode documentation warns that QEMU's syscall tracer is incomplete and that syscall translation operates through the host kernel. In particular, neither QEMU's host-syscall handling nor absence of observed `ENOSYS` proves support by the PW3's actual vendor `3.0.35-lab126` kernel.

## What R3877.49.2 changes

Uses exactly the prior R3877.49.1 pinned cached Alpine ARMv7 image, QEMU 10.0.4 helper digest, QEMU ELF SHA-256 and BusyBox SHA-256, with no downloads. Retains the same separate, explicitly authorized read-only `docker cp` gate. Only if an actual read-only filesystem failure is observed **and** the operator explicitly allows it does the test use nonprivileged, networkless, disposable writable-layer guests. It checks each stopped guest's exact argument vector, parent-image ID, user, security options, mounts and device restrictions; reads back copied QEMU bytes; runs one probe; audits the guest diff; removes the exact container and verifies the original image remains untouched. All seven probes run in separate disposable containers.

Sequence: pinned QEMU `--version`; untraced BusyBox `true`, `uname -m`, and a unique `echo` marker; then traced variants of the same three applets, all using QEMU `-0 /bin/busybox`. The **untraced controls must pass with exact stdout** before any traced probes are attempted. Each traced run must exit zero and contain parsed QEMU syscall records. The parser retains the complete **count and hash of any unclassified lines** and bounded character-class metadata; it exports no raw trace arguments, pointers, paths, or unmatched lines.

An unclassified traced line is **never ignored, attributed to the application, or treated as proof of harmlessness**. It is reported as `TRACE_OBSERVED_UNCLASSIFIED_STREAM` and `trace_output_separation_verified=false`. A limited success may be classified `PASS_QEMU_SYSCALL_NAMES_AND_UNTRACED_APPLET_CONTROLS_ONLY`, meaning precisely (a) independent untraced applets worked and (b) QEMU emitted syscall-name records in separate traced runs. It **does not** assert the traced applets' output was clean or attributable, and it does **not** retroactively turn R3877.49.1 into PASS. A failed untraced applet, missing syscall trace, changed parent image, unexpected filesystem diff, or failed cleanup remains HOLD.

## Scope and limitations

These tests establish at most an **observed QEMU-user-mode syscall-name inventory**, alongside independently verified short applet controls. Their syscall names are not a complete workload set, and the result cannot identify the original musl builder or prove target libc/TLS, threading, kernel fallback coverage, KOReader ABI, peripheral handling, recovery, or boot. Physical Kindle activity remains prohibited under the current research hold.

The package tests were run on the authoring host only, with synthetic Docker operations. **No actual Colima guest was started here.** CI must run only the host Python tests and a no-Docker preflight.
