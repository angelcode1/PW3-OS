# PW3-OS R3877.62.1 — macOS temporary-directory symlink alias fix

**For research and educational purposes only. Physical Kindle: `NOT_BOOTABLE`.** This is a Mac-only, read-only metadata inventory. It does not prove recovery, authorize a boot or firmware write, or make any Kindle connection.

## User-observed defect

The user's macOS Python 3.9 invocation of `python3 -B -m unittest -q test_r3877_62.py` reported 18 tests run, 7 errors. All seven arose in `check_root()` with `Hold('SYMLINK_IN_DIRECTORY_ANCESTRY')`, because the test's `tempfile.TemporaryDirectory()` was located under macOS's `/var` system symlink (normally `/var -> /private/var`). The prior Linux tests passed, so this specific Mac path was not exercised.

## Narrow fix

- Continue rejecting a symlink **at the selected scan root**.
- Continue rejecting arbitrary symlinks in the requested path's ancestry, and skip symlinks encountered during directory traversal.
- Allow only verified **macOS** system aliases `/var -> /private/var` and `/tmp -> /private/tmp` when they occur as *ancestors*, provided the real target is a directory, the target is not itself a symlink, and strict resolution exactly matches the known target.
- Re-check that the resolved root and all of its ancestors are not symlinks. Reject a lexical `..` in the requested root.
- Do not follow symlinked directories inside the scan. Continue scanning file names and sizes only; never read file contents or emit names, paths, or private hashes.

The tests add synthetic alias acceptance and rejection, nested symlink rejection, root symlink rejection, `..` rejection, relative directory support, and an actual macOS `/var` check when running on macOS. The host-only CI matrix includes macOS and Ubuntu.
