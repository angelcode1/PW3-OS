# PW3-OS R3877.51.1 — live symbol names, historical configuration provenance

**Research / educational purposes only. `NOT_BOOTABLE` remains immutable.**

## Why R3877.51 legitimately returned HOLD

The user supplied four files after manually collecting a read-only stock-kernel receipt over password-authenticated SSH. The first JSON predates that successful collection and contains `SSH_NONZERO_EXIT`. The later JSON reports `LIVE_KERNEL_CONFIG_UNAVAILABLE`, but the successful live receipt itself shows kernel `3.0.35-lab126`, architecture `armv7l`, `/proc/kallsyms` available and **all 14 selected symbol names PRESENT**. The device's `/proc/config.gz` and `/proc/config` provided no readable configuration in this collection. This is not an absence of the kernel features or a failure of those syscalls.

The previous R3877.21 GitHub evidence (`research/r3877-21/R3877_21_USER_REPORTED_INPUT.json`, pinned Git blob `b06ec168b5190d9b625d79449cbe09f960b037af`) separately records 14 selected Kconfig values as `AVAILABLE`, sourced from **earlier user-reported R3877.13/R3877.14/R3877.20.1 observations**. Its provenance does not authenticate the configuration of the **current running kernel image** or reveal whether its config was read directly. The original R3877.51 missing-live-config HOLD must not be silently promoted to a live-config PASS.

R3877.51.1 therefore audits two independent evidence sources while keeping them separate:

- **Current live symbol names**: reads the exact user-supplied allowlisted R51 receipt, SHA-256 `3a6f6c4e4f12284f7f340740c36605bfb012a6631c81468c9901aa76e04a665d`, and requires 14 of 14 `PRESENT`, correct kernel/arch, and `CONFIG_SOURCE|UNAVAILABLE` with 18 unknown config fields. The bundled copy is already redacted and contains no IP address, credentials, symbol addresses or full kernel configuration.
- **Historical metadata**: reads the exact previous R21 JSON, validates its Git blob SHA-1 and reports 14 historical config status values separately. These flags are **not** relabelled as live or independently verified; matching kernel release and architecture are insufficient to prove identical builds.

The only positive result is `PASS_SELECTED_LIVE_SYMBOL_NAMES_HISTORICAL_CONFIG_CONTEXT_ONLY`. This does **not** mean R3877.51's `PASS_SELECTED_LIVE_KERNEL_CONFIG_AND_SYMBOL_NAMES_METADATA_ONLY` requirement passed. `live_kernel_config_verified=false`, `actual_vendor_syscall_dispatch_verified=false`, `running_kernel_source_exact_build_verified=false`, and `NOT_BOOTABLE` remain unchanged.
